# 2026-10-28

## 项目构建方式确认
- 项目为 ESP-IDF v5.5.4 / ESP32-S3 工程（M5Stack StopWatch UserDemo），必须用 `idf.py` 构建，不能用普通 cmake。
- 依赖组件不在仓库内，需先 `python3 ./fetch_repos.py` 拉到 `components/`（含 M5IOE1/M5PM1 的 patch）。
- 配置：16MB Flash、Octal PSRAM 80MHz、240MHz CPU，自定义分区表（ota_0/ota_1 各 5MB + 4MB FAT storage）；target 由 sdkconfig.defaults 指定，无需 set-target。
- 发布打包：`idf.py merge-bin -o build/xxx-merged.bin`，从 0x0 烧录。

## 环境
- ESP-IDF v5.5.4 安装在 `~/esp/esp-idf`。
- 已在 `~/.zshrc` 增加 `esp-idf` 函数（source export.sh，支持传参切换版本，受 ESP_IDF_DIR 影响）与 `rosetta` 别名（cd 到项目目录）。
- cmake 3.30.2 / ninja 1.12.1 通过 `IDF_GITHUB_ASSETS=dl.espressif.com/github_assets python3 ~/esp/esp-idf/tools/idf_tools.py install cmake ninja` 装到 `~/.espressif/tools`（直连 GitHub 极慢，必须用镜像）。

## 构建结果（2026-10-28 首次成功）
- 修复：`main/apps/app_angle_recorder/view/view.cpp:105` 的 `std::clamp(duration, 10000, 300000)` 在 xtensa 工具链下 `int32_t` 是 `long int`，与 int 字面量推导冲突 → 改为 `std::clamp<int32_t>(...)`。
- 产物：`build/StopWatch-UserDemo.bin` 0x3a55f0 字节（约 3.6MB），app 分区 0x4f0000，剩余 26%。
- 合并固件：`idf.py merge-bin -o <绝对路径>`（相对路径会被解析成 build/build/... 而报错），产出 `build/StopWatch-UserDemo-merged.bin` 3.7MB，从 0x0 烧录。
